## Headline answers

1. **UModel zone-state offsets (all confirmed by writes quoted below):**
   - `Model+0x100` = **NumZones** (i32). Written ONLY by pass C @0xa93c0: `0x100a9552 mov dword ptr [eax+0x100], ecx` with `ecx = clamp(foundZones+1, 1, 64)`.
   - `Model+0x104` = **FZoneProperties Zones[64]**, element stride **0x18 (24 B)**:
     - `+0x00` (abs 0x104 + 0x18*i) = `AZoneInfo* ZoneActor`
     - `+0x04` = 4 B padding (never touched)
     - `+0x08` (abs 0x10c) = `QWORD Connectivity`
     - `+0x10` (abs 0x114) = `QWORD Visibility`
   - Element stride evidence: every access computes `lea ecx,[i+i*2]` then scales `*8` → 24·i
     (e.g. `0x100a79b8 lea ecx,[edi+edi*2]` / `0x100a79be mov [eax+ecx*8+0x10c], edx`).
2. **Which pass writes which field:**
   - Pass E @0xa8850 → `FBspNode.ZoneMask` (node+0x10, u64) for every node. Nothing else.
   - Pass F @0xa7960 → `Zones[i].Connectivity` (u64). Nothing else.
   - Pass G @0xa7e60 → `Zones[i].ZoneActor`, every actor's `Region` (actor+0x88..0x90),
     reverb `Delay[6]/Gain[6]` bytes on qualifying ZoneInfos, warp-zone fields
     (actor+0x37c..+0x3ac) on WarpZoneInfos, and (via Engine) each actor's zone through
     `ULevel::SetActorZone(Actor,1,1)`.
   - **`Zones[i].Visibility` (+0x114) is NEVER written anywhere in Editor.dll.** Whole-`.text`
     capstone scan for any scaled or lea-based dword write to +0x114/+0x118 found only two
     unrelated field-by-field struct-copy routines (0x100048df / 0x10009735 — bitfield-merging
     object copies, not UModel). Zone visibility is left at whatever the UModel already held
     (zero for a fresh model). The VRand helper @0xaac50 is used only for reverb raytracing, not
     zone visibility. There is NO line-of-sight zone-visibility computation in this editor.
3. **Level actors ARE touched (pass G).** ZoneInfo→zone resolution does NOT descend the BSP in
   editor code: it calls Engine's `UModel::PointRegion(ALevelInfo*, FVector Location)` (IAT
   0x100ceaa4) on each ZoneInfo's Location. The final per-actor zoning of ALL actors is
   Engine's virtual `ULevel::SetActorZone(AActor*, INT, INT)` called as `(actor, 1, 1)`.

## Pass E — 0xa8850 `BuildZoneMasks(UModel* Model, INT iNode)` (cdecl, recursive)

**Extent correction:** the function ends at `0x100a8962 ret` (int3 padding follows). The brief's
"extends to 0xa9290" is wrong — the space 0xa89a0..0xa9290 holds three OTHER functions (see
"Gap functions" at the end).

**Role:** post-CSG recursive pass computing each node's 64-bit `ZoneMask` = OR of `1<<iZone[k]`
over the node itself and its whole subtree (both children + coplanar chain). Returns the subtree
mask in edx:eax.

**Pseudo-C** (args: `[ebp+8]=Model`, `[ebp+0xc]=iNode`):
```c
QWORD BuildZoneMasks(UModel* Model, INT iNode) {
    FBspNode& Node = Model->Nodes.Data[iNode];          // 0xa8885 shl ebx,6 ; 0xa888b add ebx,[ecx+0x58]
    QWORD ZoneMask = 0;                                  // 0xa8891 movlpd [ebp-0x20], xmm0(0)
    if (Node.iZone[0] != 0) ZoneMask |= Bit64(Node.iZone[0]);   // byte at +0x34
    if (Node.iZone[1] != 0) ZoneMask |= Bit64(Node.iZone[1]);   // byte at +0x35
    if (Node.iChild[1] != -1) ZoneMask |= BuildZoneMasks(Model, Node.iChild[1]); // +0x24 front first
    if (Node.iChild[0] != -1) ZoneMask |= BuildZoneMasks(Model, Node.iChild[0]); // +0x20 back
    if (Node.iPlane    != -1) ZoneMask |= BuildZoneMasks(Model, Node.iPlane);    // +0x28 coplanars
    Node.ZoneMask = ZoneMask;                            // 0xa8947/0xa894a mov [ebx+0x10]/[ebx+0x14]
    return ZoneMask;                                     // edx:eax
}
```

`Bit64(z)` codegen (handles z∈0..63; z≥64 → 0; **z==0 is skipped entirely so bit 0 is never set**):
```
0x100a8896  mov  al, byte ptr [ebx+0x34]      ; iZone[0]
0x100a8899  test al, al / je …                ; zone 0 contributes NO bit
0x100a88a4  bts  esi, eax                     ; low dword bit (eax&31)
0x100a88a7  cmp  eax, 0x20 / cmovae edi, esi  ; if z>=32 the bit belongs in high dword
0x100a88ad  xor  esi, edi
0x100a88af  cmp  eax, 0x40 / cmovae edi, esi  ; if z>=64 → mask 0 (defensive; zones are 6-bit)
```

**Writes:** `Node.ZoneMask` (node+0x10, u64) for every node reachable from the root. Called by
portalize step 11 as `BuildZoneMasks(Model, 0)` after bspCleanup/bspRefresh/bspBuildBounds.

**Callees:** only itself. **No constants** beyond 0x20/0x40 quoted above. **Confidence: high** —
short, fully decoded.

## Pass F — 0xa7960 `FEditorVisibility::BuildConnectivity()` (thiscall, ecx=this)

**Role:** fills `Model->Zones[i].Connectivity`: seeds each zone as seeing itself, then for every
BSP node whose surface has PF_Portal, marks the node's two zones mutually connected. This is the
"which zones share a portal" graph — edges come straight from `Node.iZone[0]`/`iZone[1]` of
portal-surf nodes (NOT from the portal fragment lists).

**Pseudo-C:**
```c
void BuildConnectivity() {                 // this=ecx (FEditorVisibility), Model = this->+0x10
    for (INT i = 0; i < 64; i++)           // 0xa799c cmp edi,0x40
        Model->Zones[i].Connectivity = 1ull << i;   // writes Model+0x18*i+0x10c/+0x110
    for (INT iNode = 0; iNode < Model->Nodes.Num; iNode++) {      // [Model+0x5c]
        FBspNode& Node = Model->Nodes.Data[iNode];
        FBspSurf& Surf = Model->Surfs.Data[Node.iSurf];           // iSurf @ node+0x1c; Surfs @ +0x98
        if (!(Surf.PolyFlags & PF_Portal)) continue;              // ** PolyFlags @ surf+0x4 **
        BYTE z0 = Node.iZone[0], z1 = Node.iZone[1];              // +0x34 / +0x35
        Model->Zones[z1].Connectivity |= Bit64(z0);
        Model->Zones[z0].Connectivity |= Bit64(z1);
    }
}
```

**Key instructions:**
```
0x100a79eb  mov  ecx, [edi+0x1c]                 ; Node.iSurf
0x100a79ee  shl  ecx, 6 ; add ecx, [eax+0x98]    ; &Surfs[iSurf]  (FBspSurf stride 0x40)
0x100a79f7  test dword ptr [ecx+4], 0x4000000    ; PolyFlags @ surf+0x4, PF_Portal=0x04000000
0x100a7a00  movzx ecx, byte ptr [edi+0x35]       ; iZone[1] → &Zones[z1]
0x100a7a23  or   ecx, [esi+0x10c] / or edx,[esi+0x110]   ; Connectivity |= Bit64(iZone[0])
... symmetric block for Zones[iZone[0]] |= Bit64(iZone[1])  @ 0xa7a3b..0xa7a76
```

**New FBspSurf fact: `PolyFlags` is at in-memory offset +0x4** (Texture at +0, per prior spikes).

**Writes:** `Model+0x10c + 0x18*i` (u64 Connectivity), i = 0..63 in the seed loop, then OR-updates
for the two zones of each portal node. Zone 0 participates like any other zone in the seed
(`Connectivity[0] = 1`), but `Bit64(0)` from a portal node contributes bit 0 normally here — note
the Bit64 codegen in F does NOT skip zero (no `test al,al` guard; compare 0xa7a0a..0xa7a20 with
pass E) — a portal node with iZone[0]==0 sets bit 0 in Zones[iZone[1]].Connectivity and vice versa.

**Callees:** none. **Confidence: high** — fully decoded, no unresolved branches.

## Pass G — 0xa7e60 `FEditorVisibility::BuildZoneInfo()` (thiscall, ecx=this)

**Role:** binds AZoneInfo actors to zone slots, computes reverb Delay/Gain for
reverb-raytracing ZoneInfos, computes warp-portal coordinates for AWarpZoneInfos, then re-zones
every actor in the level. Logs `BuildZoneInfo: %i ZoneInfo actors, %i duplicates, %i zoneless`
(wide string @ 0x100fe870, EName arg 0x2f8) — the counters are (assigned, zone-already-taken,
PointRegion-returned-zone-0).

**Structure (pseudo-C):**
```c
void BuildZoneInfo() {                       // this=ecx→ebx; Level=this+0xc, Model=this+0x10
    GWarn->StatusUpdatef(0, 0, L"Computing zones");     // 0xa7eb9 call [vtbl+0x10], str 0x100fe834
    // 1. clear zone actors
    for (INT i = 0; i < 64; i++) Model->Zones[i].ZoneActor = NULL;  // 0xa7ecf [eax+ecx*8+0x104]=0
    // 2. reset every actor's Region
    for (INT i = 0; i < Level->Actors.Num; i++)          // Actors.Data +0x2c, Num +0x30
        if (Level->Actors(i))
            Level->Actors(i)->Region = { Level->GetLevelInfo(), INDEX_NONE, 0 };
            // Region: Zone* @actor+0x88, iLeaf @+0x8c (=-1), ZoneNumber byte @+0x90 (=0)
            // 0xa7f14 movq [ecx+0x88] ; 0xa7f2a mov [ecx+0x90],eax
    // 3. main per-actor loop
    for (INT i = 0; i < Level->Actors.Num; i++) {
        AZoneInfo* Actor = CastToZoneInfo(Level->Actors(i));   // helper 0xa6930
        if (!Actor) continue;
        if (Actor->IsA(ALevelInfo::StaticClass())) continue;   // 0xa7f5f call [0x100cee00]; walk
                                                               // class @actor+0x24, super @class+0x28
        Actor->Region = Model->PointRegion(Level->GetLevelInfo(), Actor->Location);
            // Location @ actor+0xd0..0xd8 (0xa7f95..0xa7fb2); PointRegion = IAT 0x100ceaa4
            // → THE BSP descent happens inside Engine.dll, not here.
        if (Actor->Region.ZoneNumber == 0) { Zoneless++; continue; }      // 0xa7fe6 test al,al
        if (Model->Zones[z].ZoneActor)     { Duplicates++; continue; }    // 0xa8002 cmp …+0x104,0
        Assigned++;
        Model->Zones[z].ZoneActor = Actor;                                // 0xa801f mov …+0x104, edi
        // --- reverb raytracing (bits 0|1 of actor+0x2b0 both set) ---
        if ((Actor->+0x2b0 & 3) == 3) ReverbRaytrace(Actor);              // 0xa8026..0xa8031
        // --- warp zone setup ---
        if (Actor->IsA(AWarpZoneInfo::StaticClass()))  WarpSetup(Actor);  // 0xa840a call [0x100cea9c]
    }
    // 4. zone every actor via the engine
    for (INT i = 0; i < Level->Actors.Num; i++)
        if (Level->Actors(i))
            Level->SetActorZone(Level->Actors(i), 1, 1);   // 0xa87ca call [LevelVtbl+0xac](actor,1,1)
    debugf(0x2f8, L"BuildZoneInfo: %i ZoneInfo actors, %i duplicates, %i zoneless",
           Assigned, Duplicates, Zoneless);                // 0xa87df..0xa87f0
}
```

### Reverb raytrace block (0xa8037..0xa8407) — gated by `(actor+0x2b0 & 3) == 3`

`0x100a8026 mov eax,[edi+0x2b0]` / `and eax,3` / `cmp al,3` / `jne skip`. The two bits are
almost certainly `bReverbZone` + `bRaytraceReverb` (inferred from the semantics below — the block
exists solely to fill Delay/Gain; bit names not provable from the binary).

Algorithm, fully decoded:
1. Local `TArray<FVector> Pairs` (ctor 0x10011be0 zeroes Data/Num/Max; element = 12 B
   `{float Delay, float Gain, float unused}`).
2. **256 rays** (`0x100a8048 cmp esi,0x100`): each iteration:
   - `FCheckResult Hit(1.0f, NULL)` — ctor 0x10062760: `+0=GetNext(arg2)`, zeroes +4..+0x20,
     `Time @ +0x24 = arg1 (1.0f)`, `Item @ +0x28 = -1`.
   - `Dir = VRand()` — helper 0xaac50 (see Callees).
   - `End = Actor->Location + Dir * 16384.f` (`0x100a80bb movss xmm3,[0x100feef0] ; f32=16384`).
   - `Model->LineCheck(Hit, NULL, End, Actor->Location, FVector(0,0,0), 0)` —
     `0x100a812a call dword ptr [eax+0x58]` on Model's vtable; arg pattern exactly matches
     Engine export `?LineCheck@UModel@@UAEHAAUFCheckResult@@PAVAActor@@VFVector@@22K@Z`
     (Engine RVA 0x1ae4c0). Slot +0x58 = UPrimitive::LineCheck (strong inference from the
     6-arg signature; slot index not independently verified).
   - `debugf(0x2f8, L"   dist=%f", (double)(Hit.Time*16384))` — string 0x100fe854; logged for
     EVERY ray (this is chatty: 256 lines per reverb zone).
   - Append `{ Hit.Time*16384 / Actor->+0x2b4, 1.0f, 0 }` unconditionally (hit or miss;
     Time stays 1.0 on a miss → delay for the full 16384 units).
     `0x100a8181 divss xmm0, dword ptr [edi+0x2b4]` → +0x2b4 = SpeedOfSound (float, inferred name).
     Append helper 0x10003650 = `FArray::Add(1, 12)` + return `Data + index*12`.
3. **Merge down to 6:** while `Pairs.Num > 6` (`0x100a81a4 cmp edx,6 / jbe`): over all pairs
   `j<i`, find min of metric `(Delay[i]-Delay[j])^2 * (Gain[i]+Gain[j])`:
   ```
   0x100a81e3 movss xmm0,[edi+ecx*4] ; subss xmm0,[edi+eax*4]     ; Δdelay
   0x100a81ed movss xmm1,[edi+eax*4+4] ; addss xmm1,[edi+ecx*4+4] ; gain_j+gain_i
   0x100a81f9 mulss xmm0,xmm0 ; mulss xmm1,xmm0                    ; (Δd)^2·(g_i+g_j)
   ```
   (best initialized to (i=0, j=1) with metric 9.999999827968e12 from `[0x100feef4]`).
   Merge into slot i: `Delay[i] = (g_i·d_i + g_j·d_j)/(g_i+g_j)`, `Gain[i] = g_i+g_j`
   (0xa822a..0xa82d8), then `Pairs.Remove(j, 1)` (0x10045c40, bounds-asserted TArray remove).
4. **Sort ascending by Delay** — O(n²) swap sort, 0xa82ee..0xa836f.
5. **Quantize to the actor's byte arrays** (0xa8371..0xa83f8), double-precision constants:
   `[0x100feee8] f64=255.0`, `[0x100fe190] f64=1000.0`, `[0x100de948] f64=0.00390625 (=1/256)`:
   - `Actor->Delay[i] (byte @ actor+0x2c0+i) = clamp((double)Delay[i] * 1000.0, 0, 255)`
     (delay is seconds if SpeedOfSound is units/sec → stored in milliseconds).
     `0x100a83ba mov byte ptr [esi+edi+0x2c0], al`
   - `Actor->Gain[i] (byte @ actor+0x2c6+i) = clamp((double)Gain[i] * 255.0 * (1/256), 0, 255)`
     (each of the 256 rays contributes gain 1.0, so the sum of all gains maps to ≈255).
     `0x100a83e8 mov byte ptr [esi+edi+0x2c6], al`
   Exactly 6 entries remain (256 → 6 by one-removal-per-iteration), so all 6 slots fill.

### Warp-zone block (0xa8431..0xa87a3) — only for `Actor->IsA(AWarpZoneInfo)`

1. `iLeaf = Actor->Region.iLeaf` (+0x8c); bail if -1.
2. `FPortal* Portal = this->LeafPortals[iLeaf]` — `0x100a8440 mov eax,[ebx+0x10050]` /
   `mov edi,[eax+edi*4]`; bail if NULL. **So this+0x10050 is a per-leaf `FPortal*` array** (the
   leaf's zone-portal), not a plain INT list.
3. Bail if `Portal->iSurf == -1` (`0x100a8454 cmp dword ptr [edi+0x1fc], -1`). **FPortal layout:**
   FPoly (0x1d8 bytes: Base+0, Normal+0xc, Vertex[0]+0x30) followed by `iFrontLeaf @ +0x1d8`,
   `iBackLeaf @ +0x1dc` (proved by helper 0xa96a0), a next-pointer `@ +0x1e4` (pass C's chain
   walk `0x100a9472 mov edi,[edi+0x1e4]`), and a surf index `@ +0x1fc` (-1 = plain portal,
   ≥0 = backing PF_Portal surf).
4. `FBox Box(0)` (Core `??0FBox@@QAE@H@Z`); for EVERY node with `Node.iSurf == Portal->iSurf`,
   accumulate all its vertices: `Box += Points[Verts[Node.iVertPool + v].pVertex]`
   (0xa8471..0xa84d9; Verts.Data @Model+0x68, entry stride 8, pVertex first dword;
   Points.Data @Model+0x88; Core `FBox::operator+=`).
5. `Mid = (Box.Min + Box.Max) * 0.5` (`[0x100dcb10] f32=0.5`), then project onto the portal
   plane: `Proj = Mid - Portal->Normal * (Portal->Normal · (Mid - Portal->Vertex[0]))`
   (0xa85e3..0xa86a3; Normal @Portal+0xc, Vertex[0] @Portal+0x30).
   - `Actor->+0x380..0x388 = Proj` (0xa86ae..0xa86be) — WarpCoords.Origin.
6. From `Surf = Surfs[Portal->iSurf]`: three vector indices at surf+0xc / +0x10 / +0x14 index
   `Model->Vectors` (+0x78); each is passed through Core `FVector::SafeNormal`:
   - `Actor->+0x3a4 = SafeNormal(Vectors[Surf.+0xc])`  → ZAxis (surf normal; so **surf+0xc = vNormal**)
   - `Actor->+0x38c = SafeNormal(Vectors[Surf.+0x10])` → XAxis (**surf+0x10 = vTextureU**)
   - `Actor->+0x398 = SafeNormal(Vectors[Surf.+0x14])` → YAxis (**surf+0x14 = vTextureV**)
   Net: `Actor->WarpCoords` = FCoords {Origin @+0x380, X @+0x38c, Y @+0x398, Z @+0x3a4}
   (field name inferred; offsets exact).
7. `Actor->+0x37c = Model->Leaves[ Portal->OtherLeaf(Actor->Region.iLeaf) ].iZone` —
   helper 0xa96a0 returns iBackLeaf if arg==iFrontLeaf else iFrontLeaf (appErrors if neither);
   Leaves stride 0x14, iZone at +0 (`0x100a878e lea ecx,[eax+eax*4]` / `mov eax,[eax+ecx*4]`).
   I.e. **the zone index on the far side of the warp portal** (presumably `iWarpZone`).

**All state written by G:** `Model.Zones[*].ZoneActor` (+0x104+0x18i); every actor's
`Region` {Zone,iLeaf,ZoneNumber} @ actor+0x88/0x8c/0x90 (reset, then per-ZoneInfo via

## Context confirmations from pass C @0xa93c0 (zone flood — decoded for the offset deliverable)

- Walks the global portal chain at `this+0x10044` (next @ portal+0x1e4). For each portal whose
  `+0x1fc == -1` (NOT backed by a PF_Portal surf) it MERGES the zones of its two leaves:
  reads `zA = Leaves[iFrontLeaf].iZone`, `zB = Leaves[iBackLeaf].iZone`, then rewrites every
  leaf with iZone==zA to zB (0xa941e..0xa9470). Portals WITH a surf index (zone portals) do not
  merge — that is exactly what makes PF_Portal surfaces zone boundaries.
- Renumbers leaf zones compactly to 0..N-1 (0xa947a..0xa94ec), logs
  `debugf(0x2f8, L"Found %i zones", N)` (string 0x100fe6f0).
- Remaps every leaf `iZone = (iZone % 63) + 1` (`0x100a950e mov dword [ebp-0x2c],0x3f`,
  `0x100a952f idiv` / `inc edx`) — zones occupy 1..63, zone 0 = outside.
- `Model->NumZones = clamp(N+1, 1, 64)`:
  ```
  0x100a953b inc edi ; cmp edi,1 ; jge → mov ecx,0x40 ; cmp edi,ecx ; cmovl ecx,edi
  0x100a9552 mov dword ptr [eax+0x100], ecx
  ```
- FBspLeaf confirmed stride 0x14 with iZone at +0 (`lea ecx,[i+i*4]`, `[Data+ecx*4]`).
